# EIT p/f と終了時刻未定

参照した仕様書（ローカルの `~/Documents/ARIB`）：

- ARIB STD-B10 v5.13 第2部 5.2.7、p.101：緊急ニュースなどの終了未定は duration 全ビット1。
- ARIB TR-B14 v6.7 第4編 6.1、p.4-21：同一サブテーブルのセクションは同一 version_number。
- 同 13章、pp.4-84–85：p/f は各1セクション。空セクションも有効。
- 同 19.1–19.3、pp.4-145–147：時刻未定でも event_id は有効。両時刻未定の following は番組自体が未定で event_id は無意味。present から消え、following にも存在しない番組は終了。割り込みで中断された番組は開始時刻を変えず following に移り、再開時に present に戻る。
- 同 C.5.7–C.5.8、pp.4-428–429：未定時刻をそのまま扱い、p/f を優先。schedule との不整合を考慮する。
- ARIB TR-B39 v2.5 第4編 20.1–20.3、pp.4-99–101：MH-EIT にも同じ終了未定・中断・再開の規則がある。

## 保存方針

TS の actual p/f と MH-EIT p/f について、同じ版の present/following が両方揃ってから、一つのトランザクションで反映する。空セクションも状態の更新として扱う。他 TS の p/f は actual の状態を置き換えない。

p/f が有効な番組の時刻・基本情報は schedule で上書きしない。同じ event_id の時刻確定は通常の更新として反映する。開始・継続時間とも未定のプレースホルダーは保存しない。

present から following に移った番組は中断として保存し、両スロットから消えるまで保持する。終了が確認できた終了未定番組は、終了時刻を推定せず番組一覧から削除し、remove 通知を発行する。これは番組一覧の保存方針であり、仕様が履歴の削除を要求しているわけではない。終了時刻が既知の番組は履歴を残し、p/f の状態だけ解除する。まだ present になっていない following が消えただけでは放送終了・休止と断定しない。

過去に受信した EIT の全変更履歴は保存していない。この修正で、昨晩放送された終了時刻付き更新の有無を遡及的に証明することはできない。既存の終了未定番組は対象サービスの完全な p/f を次に受信したときに整理される。

## remote の番組情報

remote の create/update/remove 通知を受信順に反映する。remove の直前には保留中の更新を保存し、同じ ID の削除後の再作成と順序が逆転しないようにする。削除は既知サービスに限定し、保存成功後に通知する。

定期同期では、remote 一覧の最古の開始時刻以降にかかる番組に加え、終了時刻未定の残存番組も置換対象にする。一覧にない未定番組を削除することで通知欠落から回復し、対象期間より前に終了した時刻既知の履歴は保持する。取得失敗時には置換しない。この経路では remote の一覧・通知を正として扱い、p/f の中断・再開の判定自体は remote に任せる。
